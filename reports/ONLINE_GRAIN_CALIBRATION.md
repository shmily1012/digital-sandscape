# GPU 当前位置颗粒校准参考

## 后续：有界批次与明确拒绝原因

新增 `grain_status.glsl`，GPU 汇总所有压力系统、迁移率证书和候选状态为 16 字节。状态码区分接受、需要更多迭代、非法数值、非正定迁移率和候选越界。上层只对“需要更多迭代”重试，最多 12 批×8 循环。候选拒绝时状态仍保持，不能把一次尝试算作物理时间步。

`python run.py batched-grains` 检查 8 个成功物理步，每批失败时额外读回验证原字节未变（测试专用）。结果与 96 循环基准逐步位置误差相同，failures=0；预算不足返回可重试原因，密集负耗散返回不可重试原因。76 项 CPU 与旧 GPU 守恒回归通过。

这轮每步 GPU 时间之和：温启动六步约 20.6–21.5 ms，各需两批；首次冷启动 68.9 ms、反转步 51.9 ms，各需六批。同轮 96 循环基准约 47.3–52.7 ms。由此可见小批次改善部分步骤，冷启动甚至更慢，**不能称为可扩展或预算达标的快速校准**。测量只有八步，不是稳定 p95；该局部设备验证包含测试同步，不代表主设备实时延迟。

进一步优化必须减少独立响应系统的数量或使用可验证的近似，而不能只改批大小。精确路径继续保留为参照，不接入默认窗口。

新增 `grain_calibration.glsl` 和 `online_grains.gd`。每一步从当前 GPU 粒子位置生成归一化权重，对每粒两个方向施加 0.001 的试探力，分别求解压力并还原单位响应；生成完整粒子迁移率与自身 2×2 块。GPU Cholesky 检查修正矩阵的对称性与正定性，失败时将候选标无效，整批位置保持原状。最后使用真实外力推进。独立 pass、barrier 和独占写入保证无跨 invocation 写冲突。

没有上传逐步 CPU 校准矩阵，没有中途 CPU 粒子场读回；CPU 参考轨迹只用于每步完成后的测试比较。只支持 32²、1–8 颗粒，超过上限在分配前拒绝，避免无界校准工作。

## 真实结果

Godot 4.7.2 / Windows Vulkan / RX 7900 XTX：

- 三颗粒 8 步、dt=0.02，四步后反转斜向重力，CPU/GPU 最大位置差 7.88e-8；自身响应块最大差 3.77e-4。
- 材料、半径、阻力、密度字段逐字节保持；每步校准由更新后的 GPU 位置重新产生。
- 只给一次压力循环时拒绝且状态不变；随后完整预算能继续。
- 重叠密集配置的修正迁移率非正定，被 GPU 检查拒绝，粒子字节不变；这不是接触处理。
- 76 项 CPU 与旧 GPU 1000 tick 守恒回归通过。

## 成本与限制

本轮八步 GPU 时间戳约 47.1–52.4 ms/步（包含 2N+1 次压力求解、各自最多预排 96 次循环；不是预热后的稳定 p95）。仅三颗粒就明显不符合低资源产品目标，因此保留为正确性参考，不接入默认实验窗口。后续可以减少预排命令，但 2N 校准求解本身仍不能直接扩展到大量沙粒，需要可验证的响应近似或查表方法。

校准仅针对当前均匀 Darcy 算子，仍未处理颗粒体积排除、密集接触、近壁润滑或气泡阻挡。数值正定检查不等于科学物性标定。完整产品目标未完成。
