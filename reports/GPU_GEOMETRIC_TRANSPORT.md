# GPU 几何气液界面输运（2026-10-24）

## 实现

新增 `geometric.glsl`、`geometric_gpu.gd`，将已有 CPU 几何输运移到 GPU。每一步有五个明确分隔的 pass：当前相分数的局部直线重建、面扫掠体积、cell 通量限幅预算、共享面修正量、cell 状态更新。cell pass 独占 cell，face pass 独占 face；各 pass 和步骤之间 barrier；状态双缓冲，无跨 invocation 写竞争或浮点原子加法。

几何只从当前状态重建，没有每步拟合圆泡或生成山脉。float32 使用 26 次偏移二分和 1e-6 限幅余量；CPU 对照使用 double 精度，因而比较数值容差而非逐字节一致。零流动单独要求字节一致。

每次调用最多 256 步；依据当前初始化时给定的面速度验证出流 CFL，拒绝非有限或过大步长，不改变状态奇偶性。**面速度目前固定且由测试夹具给定**；今后接入 GPU 压力输出时必须重新计算 GPU CFL，不能继续使用旧的缓存界限。

## 失败及修复

初版圆形回流测试在 50 步后出现最大相分数 1.0000020266，略超过原定 1+2e-6 阈值，失败。原因是 float32 反复累加小通量时的误差累积。改为先累加共享面总变化，再以 `precise` 中间量进行补偿累加；没有裁剪 cell 相分数或添加气体，没有放宽门槛。

新增每 cell 浮点补偿缓冲，是状态的一部分。未来快照/恢复、回滚和重放必须保存它，不能只保存显示的相分数。

## 实机验证

运行：

```powershell
python experiments/liquid/geometric_fixtures.py
python run.py geometric
```

Godot 4.7.2 / Vulkan / RX 7900 XTX，**5/5 场景通过**：32² 平移、斜向运动、封闭矩形涡流、封闭圆形回流各 50 步；16² 零流动 10 步。测试检查 CPU/GPU 差、气体总面积、相分数上下界、圆外零状态、零流动字节一致，以及超步数/非法 dt/超 CFL 请求不修改状态。

修复后的最大相分数差约 2.0424e-6，最大气体面积误差约 2.8397e-10。五组最终相分数观测值均在 [0,1]，不据此承诺任意长期运行严格无舍入误差。预设门槛为相分数差 3e-4、气体面积误差 1e-6、上下界容差 2e-6；未在失败后放宽。

单次未预热 GPU timestamp：32² 一整批 50 步约 4.45–4.82 ms。包含五个 pass 的重复执行，不含压力、曲率、颗粒接触、CPU 夹具生成和画面渲染；不是完整应用耗时或稳定帧率保证。详见 `geometric-gpu-validation.json`。

全量 CPU 66/66 通过；`python run.py gpu` 原工程 1,000 tick 守恒回归 0 failures。CPU 参考没有换成 shader 的逐句镜像，而是继续使用原 double 多边形裁剪实现。

## 未完成及下一步

这只是两相气液输运，不含三种沙粒身份/接触、毛细力生成、压力求解或动态旋转输入。圆形夹具的面速度由 CPU 压力参考预先计算一次，后续直接演化实时状态；不能把它称为完整气泡动力学或 GPU 三相耦合。

目前使用 local RD 做差分测试；模块接受外部 RD，但尚未在主设备异步物理任务中集成验收。下一步将已发布压力转换为 GPU 面速度，添加动态 CFL 和候选状态完整校验，再接入主设备事务。产品主程序尚未替换，整体目标仍未完成。
