# 主设备异步压力任务（2026-10-24）

## 实现

新增 `async_pressure_job.gd`，在 Godot **主 RenderingDevice / render thread** 上执行压力任务。没有主设备 submit/sync，也没有正常路径的整场读回。使用 [Godot 官方异步缓冲读取 API](https://docs.godotengine.org/en/4.4/classes/class_renderingdevice.html)，每包只取 16 字节收敛状态；实机版本为 Godot 4.7.2。

每个任务先发一包只检查残差的命令；未收敛时每包最多 8 个 V-cycle，任务最多 128 个循环。上一包状态回调完成前不提交下一包，不接受第二个并发任务。状态回调只延迟通知主线程，所有 RD 操作回到 render thread。

增加独立的已发布压力缓冲。候选仅在收敛后复制到该缓冲；超预算、非法输入、及时取消均拒绝发布，并把候选压力恢复为上一份已发布值，避免下一次温启动继承未验收结果。`publishing` 是事务决议点；此后已排队的发布不可撤销，`cancel()` 返回 false，关闭等待发布/回调结束再释放。

关闭时不会提前释放仍有异步回调引用的资源。正常调度只读 16 字节；独立验证脚本使用明确命名的 test-only 整场捕获来检查发布结果，没有把该路径接入产品渲染。

## 实机验证

`python run.py async-pressure`：主设备 Vulkan / RX 7900 XTX，六个连续任务及在途关闭检查，**0 failures**。

| 场景 | 实际循环 | 状态包数 | 状态读回字节 | 发布结果 |
|---|---:|---:|---:|---|
| 冷启动 | 55 | 8 | 128 | 收敛并发布 |
| 方程不变 | 0 | 1 | 16 | 压力字节保持不变 |
| RHS 增加 1% | 39 | 6 | 96 | 重新收敛并发布 |
| 反向 RHS，仅给 1 循环 | 1 | 2 | 32 | 拒绝，已发布内容不变 |
| RHS 含 NaN | 0 | 1 | 16 | 拒绝，已发布内容不变 |
| 求解期间取消 | 0 | 1 | 16 | 拒绝，已发布内容不变 |

每次成功压力与 CPU 参考比较，最大分量误差约 2.02e-8。验证还覆盖重复 start 被拒绝、失败不增加发布版本、异步回调未完成时关闭，以及关闭后无在途状态。

最初脚本存在类型推断解析错误，已显式声明初始化结果为 bool；失败测试进程已按本项目脚本路径停止。最终两次运行均完成并正常退出，不能把首次启动失败计入通过。

`python -m unittest discover -s tests -v`：66/66 通过；`python run.py gpu`：1,000 tick 旧基线守恒 0 failures。最终 `async-pressure.log` 检查无 ERROR / SCRIPT ERROR / invalid ID。未修改 GLSL 物理规则。

## 延迟与性能边界

最新单次任务墙钟延迟：冷启动约 118.1 ms、方程不变约 16.1 ms、1% 变化约 99.5 ms。它们包含帧队列、CPU 调度及等待回调，**不是 GPU 时间**，不能与上一报告的 GPU timestamp 直接相减得出加速比。本轮测试帧率上限 120，后台/低帧率时回调延迟仍须测量。

相比预排 96 轮，正常温启动只有一次检查包，不再排空循环。代价是收敛期间要跨多个渲染帧等待状态，因此完整物理的更新率和受控慢时间仍待评估。
