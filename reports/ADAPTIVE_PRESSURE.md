# GPU 残差控制与压力温启动（2026-10-24）

## 本轮实现

新增 `residual_control.glsl`，GPU 在每个 V-cycle 前及最终完成后计算压力方程最大残差，输出残差、收敛标志、实际执行循环数、非有限输入标志。控制缓冲同时保存各层 indirect dispatch 参数；收敛后工作组数设为零。一次提交期间无需 CPU 读回作迭代决定。

使用 Godot 官方的 [RenderingDevice 间接 dispatch API](https://docs.godotengine.org/en/4.4/classes/class_renderingdevice.html)，控制缓冲带 `STORAGE_BUFFER_USAGE_DISPATCH_INDIRECT` 标志，实机在当前 Godot 4.7.2 验证。这里链接的是公开 API 文档，不据此声称所有 Godot 版本和平台已测。

压力双缓冲持续保留，更新 RHS 不清空压力。GPU 收敛后将已接受压力镜像到另一个细层缓冲，避免预排命令仍改变 CPU 记录的 ping-pong 奇偶性而读到旧结果。统计信息每次求解重置，压力不重置。每包上限明确限制为 1–128 个循环。

CPU 参考同步支持初始压力；新增测试证明相同方程直接复用，而方程变化后必须重新检查/求解。

## 实机结果

`python run.py adaptive` 使用同一个 GPU 求解器实例、持续压力缓冲，按顺序测试 32² 圆形沉降方程：

| 场景 | 实际求解循环 | 收敛 | 非有限输入 | 独立残差 |
|---|---:|---|---|---:|
| 冷启动 | 55 | 是 | 否 | 1.90735e-6 |
| RHS 不变 | 0 | 是 | 否 | 1.90735e-6 |
| RHS 增加 1% | 39 | 是 | 否 | 1.66893e-6 |
| RHS 反向、预算仅 1 次 | 1 | 否 | 否 | 0.628806 |
| RHS 注入 NaN | 0 | 否 | 是 | 非有限 |

GPU 在线阈值为 2e-6；整包结束后测试读回压力，用 CPU double 独立重算方程残差，并与 CPU 参考比较。通过场景压力差最高约 2.02e-8，保留原状态差 2e-6 / 独立残差 1e-5 门槛。RHS 不变场景压力字节完全不变；非有限输入场景未推进压力。预算耗尽场景只产生未收敛的候选压力，**不得交给物理推进**；完整产品事务提交门控尚未接入。

全量 `python -m unittest discover -s tests -v`：**66/66 通过**。`python run.py multigrid` 六组原 GPU 对照和 `python run.py gpu` 的 1,000 tick 沙粒守恒回归通过。

## 性能反例，而非预算达标

首次计时读取顺序错误，在数据读回后查询 timestamp 得到无效值；已改为先取计时，再作测试读回。有效单次未预热 GPU 测量：冷启动约 11.53 ms、相同 RHS 约 7.09 ms、1% 变化约 10.40 ms。即使零个有效循环，仍有预排 96 轮命令和 barrier 的开销。**不能把有效循环减少解释为 GPU 开销趋零，也不能把此方案称为已优于上一版固定迭代。**

当前残差归约只使用一个 64 线程工作组遍历全场；只测了小网格，不宜外推到 256²/512²。时间均不是稳态基准、利用率或桌面预算保证。
