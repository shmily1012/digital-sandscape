# 两相求解 GPU 预算与小批量调度

## 最新：条件输运合并，恢复单轮延迟

每个 8 循环压力包现在紧接受 GPU 收敛门控的输运/着色。未收敛时只复制原界面，补偿缓冲不变；收敛才实际输运。两份 16 字节状态通过 GPU buffer copy 合为一次 32 字节异步读回，不再等待 CPU 后单独发起输运。一个物理任务仍最多 96 循环且仅单任务在途。

本轮局部基准（10 预热 + 60 样本）：预排96 / 分批8 / 合并8 的 GPU p50 分别为 8.289 / 1.082 / 1.007 ms，p95 为 8.783 / 2.094 / 2.022 ms。合并策略的压力阶段时间包含条件输运和着色，不能与原来纯压力阶段直接比较。三者最终 CPU 参考误差均为 2.125e-5。

主设备 200 步再次通过，完成延迟中位数 66.375 ms（前版约 133 ms），218 批共 6976 字节状态读回，体积分数差 2.008e-5；在途关闭退出码 0。该延迟仍包含渲染帧与回调等待，不是 GPU 时长。

新增 `python run.py lab-rejection`：冷启动只给 8 循环，确认压力预算拒绝后界面逐字节相同、tick/time 为零；重试 96 循环从同一状态成功推进一步，CPU 误差 5.96e-8。在途重复提交被拒绝。69 项 CPU 与旧 GPU 守恒回归通过。

下一步回到颗粒与两相耦合；目前所有预算数据只覆盖 32² 单泡实验，不能替代 256²/512²、三材料接触或桌面后台干扰测试。以下是先前测量与改动记录。

## 实测基准

`python run.py coupled-benchmark`，RX 7900 XTX / Godot 4.7.2 / Vulkan，32² 当前状态驱动的毛细、浮力、压力与输运。每种策略独立初始化，10 步预热、60 个计时样本，最终均与同一 CPU 参考核验。

| 策略 | 总 GPU p50 | 总 GPU p95 | 压力平均 | 曲率/浮力平均 | 输运/着色平均 |
|---|---:|---:|---:|---:|---:|
| 每步预排 96 循环 | 8.617 ms | 9.273 ms | 8.483 ms | 0.036 ms | 0.125 ms |
| 每批 8 循环，收敛停止 | 1.069 ms | 2.163 ms | 1.078 ms | 0.020 ms | 0.123 ms |

两者最终体积分数对 CPU 最大误差相同，为 2.125e-5。以上是 local RD 分阶段提交的 GPU 时间戳之和，排除 CPU 等待、Canvas 和主设备调度；不是利用率，也不代表 256²/512² 可达同样性能。主要收益来自少提交无效压力命令，不能归因于物理精度降档。

## 主设备改动和代价

`live_cell.gd` 每批最多 8 次压力循环，16 字节异步残差检查后决定继续，累计最多 96 次。收敛后才提交输运/着色，保持单个物理任务在途；压力检查期间关闭会等待回调后释放，不继续提交输运。粒子/气相不重新初始化。

`python run.py lab-smoke`：200 步、总时间约 0.1、218 个压力批、6688 字节状态读回，通过最终状态对照与在途关闭，正常退出 0。最大体积分数差 2.008e-5，面积误差 6.10e-10。69 项 CPU 与旧 GPU 1000 tick 守恒检查通过。

**代价**：主设备完成延迟中位数 133.046 ms，较上一版本约 66 ms 增大；这源于压力检查与输运之间的新异步轮次，而非 GPU 算得更久。当前选择降低 GPU 命令成本，尚未达到流畅且低资源的产品目标。6688 字节为验证的 200 步，不包括最终完整状态测试读回及关闭测试的额外任务。

将有条件的输运与最后压力包合并，保留 GPU 收敛门控并减少一次回调轮次；继续测量主设备实际时间与延迟。之后才能依据真实预算扩网格、连接颗粒。仍无用户 GPU 百分比保证、前台程序/电池信号或完整 AdaptiveResourceManager 产品功能。
