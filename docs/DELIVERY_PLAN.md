# 面向产品的交付恢复计划

当前决策：冻结独立连续颗粒/压力求解器扩展。保留 experiments 的源码与失败证据，不再把新增局部实验数量作为产品进度。主应用采用可解释、可守恒、低成本的有效物理近似，按可见行为决定下一步；不承诺科学级 CFD。

## 当前主应用

`python run.py app` 已使用三色沙/液体/气体的保守格点候选。六类状态为液体、三种沙、墙、气体。气体与液体交换上浮，邻域气体键合偏好抑制碎散；沙只与液体交换，不能穿过气体。颜色移动率仍是未标定的有效沉降参数，不声称模拟真实矿物配方。

这不是完整流场：没有液体压力/速度求解、润湿薄膜、气泡可压缩性或精确表面张力。气体不能直接与沙交换可能造成持久阻塞，必须通过完整循环观察，而不能以守恒测试代替验收。当前粗糙堆积和气泡格点轮廓还不能作为成品视觉。

## 下一步的验收顺序

1. 主应用连续演化：至少完整沉降、180 度翻转、再沉降的实际录屏/截图与计数记录；检查是否长期卡住、气泡是否失去形状、山峰是否自然生成。截图按 tick 命名，不把任意时刻称为稳态。
2. 释放与堆积：比较相同沙库存的有气/无气运行；检查气体改变局部供沙而非纯装饰；改善孤立沙的横向数值扩散和堆积坡面。每次变化回到主窗口验证。
3. 视觉：提高颗粒细腻度、界面和圆框观感。不得由 renderer 创建地形或掩盖物理重置。以相同物理状态比较渲染。
4. 低负载与使用：在主应用量测完整 GPU/CPU 成本、休眠和资源档位，增加快照恢复与摆件窗口。
5. 桌面交付：Windows 打包/壁纸宿主适配；macOS 兼容性、打包与未验证项单列。系统设置及壁纸变更仍需遵守用户授权范围。

每一步必须交付实际应用变化及证据；只修正阻碍这条可见链路的问题。不得以这份恢复计划缩减原来的 Windows/macOS、持久状态、模块分离、资源预算和桌面集成目标。
