# 接触与载液共同求解：CPU 参考边界

此文件描述 `experiments/deposition/coupled_contacts.py`，不替代现有 GPU 实现，也不宣称已得到完整流沙画。

## 一致的力与速度

令 `F` 为扣除静水浮力的重力，`J` 为接触法向/切向相对速度算子，`lambda` 为接触反力。颗粒对载液的净作用力为：

`Q = F + J^T lambda`

在当前无惯性的点力近似中，颗粒速度为：

`v = M Q`

`M` 包含封闭 Darcy 载液的传播响应，并将单粒子自身响应替换为指定的局部阻力倒数。它依赖当前位置，每次重新标定；对称性与正定性必须检查，不能假设任意浓度下都成立。

载液使用同一组归一化面权重来分配 `Q` 和采样速度，再经过封闭压力投影。因此传力与速度采样的离散功互为转置。尤其不能仍把 `F` 单独传给载液：静止且完全由壁面支撑的颗粒应满足 `Q=0`，不应持续驱动液流。

接触满足非穿透和有效库仑摩擦，法向与切向更新分别使用 `Jn M Jn^T`、`Jt M Jt^T`。一次接触反力变化会通过 `M` 改变所有颗粒的速度，而不只是接触对本身。这正是已有 GPU 局部倒阻力求解器尚未包含的耦合。

## 现有实现

- `contact_particles.advance_contacts(..., mobility_matrix=...)` 接受可选完整移动率矩阵；默认仍为原局部模型。
- CPU `advance_coupled` 用真实压力投影标定矩阵，求接触反力，再将包含反力的净载荷投影回载液。
- 返回参考误差：载液反算速度与接触速度的差、合力分配误差、离散功互易误差。
- GPU 串行接触参考新增 `FULL_MOBILITY` 编译变体，按已知完整矩阵更新全部颗粒速度，并从最终反力重建速度后验收。当前矩阵仍由 CPU 压力标定后上传；这不是完整 GPU 联合求解。CPU 失败不返回部分更新，GPU 拒绝保留输入颗粒。
- 现有 `contact_refinement.py` 仍仅适用于局部阻力；不能直接用它为完整矩阵耦合失败兜底。GPU 并行接触、活跃矩阵构造、最终提交检查也必须共同支持新的移动率后才能集成。

## 验证与未覆盖项

六项新增测试覆盖：局部对角矩阵退化一致、静止支撑颗粒停止驱动液流及翻转释放、无接触极限对照、接触反力反馈与功互易、非对称/非正定矩阵拒绝、双颗粒 80 步沉降到支撑面再翻转的持续状态/身份/非穿透/封闭散度。

支撑面为隔离测试用的平面，不是气泡。测试是无量纲、小颗粒数 CPU 参考，不能外推真实黏度/颗粒尺寸，也不能证明 GPU 速度或图像观感。

当前模型没有固体排开液体的体积约束、颗粒自转、润滑、气泡排斥或毛细接触。浓沙层可能使自响应修正后的矩阵失去正定性，当前明确拒绝。下一步必须先明确浓相使用范围及压力/接触一致性，再移植联合 GPU 更新；不能给现有落沙模型简单叠加一个流速场就声称完成耦合。

## 持续联合 GPU 周期与压力精度判据

```powershell
python experiments/deposition/coupled_cycle_fixtures.py
python run.py coupled-cycle
python experiments/deposition/coupled_cycle_verify.py
```

`coupled_contact_gpu.gd` 仅在初始化上传粒子；每步把已发布的 GPU 粒子复制到只读输入快照，重新标定移动率、求接触和最终压力，再共同发布。80 步（dt=.005，60 步沉降/支撑、20 步反转）完成 0.4 模拟时间。反转处先故意给最终压力不足预算，粒子/旧液流/模拟时间保持，随后从同一状态成功重试。完整读回仅在验证器中，模块本身不读回。

首次第一步遭遇 float32 压力精度地板：原绝对门限 2e-6 下运行 96 轮仍拒绝，但 GPU 液流与 CPU 解仅差 4.30e-8；将 CPU 高精度压力量化为 float32，散度也达到 2.38e-6。为避免把不可能达到的绝对阈值当作收敛目标，最终反馈路径显式启用：

`pressure_threshold = 2e-6 + 4 * float32_epsilon * max(abs(rhs))`

这是工程混合判据，并非严格的舍入误差上界。默认压力路径仍使用绝对门限，原收敛/预算耗尽/非有限值检查保持通过。独立 double 散度审计允许另 1e-6 跨计算精度差，并同时坚持 CPU 液流对照最大差 <=2e-6；没有用新的压力阈值代替液流精度检查。接触残差和几何门限未改。

80 帧独立审计通过：最大接触残差 1.35e-7、载液通量差 1.40e-6、最大散度 8.58e-6（符合上述载荷相关判据）；整条轨迹与 CPU 位置最大差 2.10e-7。单次周期的 GPU 步耗时 p50 36.00 ms、最大 41.31 ms；只有两粒、32² 网格，尚不适合产品规模。

仍缺：主设备异步联合调度、气泡界面、固体排液/润滑、自转、大规模可扩展性与艺术窗口接入。80 步两个方向不是任意角度、长稳或自然山脉验收。


## 有界分批标定与主设备异步验证

```powershell
python run.py mobility-packets
python run.py async-mobility
```

新增 `mobility_packets_gpu.gd`：每个单位载荷压力解按 1–8 轮分包继续，累计每列不超过显式预算（上限 128 轮）；只有收敛列才采样，全部列完成后才认证并发布矩阵。未收敛、取消或非法状态时不报告矩阵可用。颗粒完全不由该模块推进。每包必须先完成状态消费，才能记录下一包，禁止重复排队。

每包 8 轮与每包 1 轮在本地 GPU 上均生成与整批标定逐字节相同的矩阵，CPU 参考最大差 3.39e-4。单次测量的最大包耗时约 1.77 ms / 0.46 ms；总 GPU 约 33.77 ms / 32.22 ms，说明分批主要降低最长连续工作，而不是消除求解成本。

`async_mobility_job.gd` 在主 RenderingDevice 上通过 render-thread 记录和异步状态回调续算。一次只允许一包在途，正常压力状态 16 字节，最终证书 4 字节；测试-only 接口才读取完整矩阵。预算耗尽后重试成功（27 包、420 状态字节）、取消及在途关闭通过。状态拥有者与设备操作分离，关闭等待在途回调后释放资源。

此异步作业目前仅负责压力标定，并没有包含接触/最终压力反馈/颗粒提交。完整联合求解仍使用已有同步验证器，下一步需把这些阶段接入同一可取消事务，不能宣称联合模型已异步化。


## 完整主设备异步联合事务

```powershell
python run.py async-coupled
```

该命令依赖已生成的 `coupled-cycle-fixtures.json` 和同步周期 trace。新增 `coupled_packets_gpu.gd`、`async_coupled_job.gd`，顺序连接分批标定、接触、分批最终压力、联合验证和发布。压力每包最多 8 轮、每个压力解最多配置预算，单次只允许一包在途；正常状态回调仅 4/16 字节，主线程不 submit/sync。接触仍是单个有迭代上限的串行包，未证明在更大规模下满足毫秒预算。

最终反馈模块拆成 prepare / pressure_packet / validate_candidate / publish_candidate。联合验证通过后仍未写物理输出；主线程先处理取消意图，再进入 publishing 决策点，之后排入颗粒/液流共同发布。发布完成回调推进 tick/time。取消只在发布决策点之前有效；发布已经排队后不伪装撤回，close 等待完成后释放。传输/排队错误进入 failed，不能自动重试可能已经发布的事务；该错误路径尚未做故障注入验收。

主设备 80 步、.4 模拟时间通过，最终粒子与面通量均和同步 trace 逐字节一致；第 61 步预算失败后恢复通过。在最终验证已通过、发布前取消额外一步，已有粒子/液流/时间均保留；在途 close 和重复 start 拒绝通过。正常与负例共回传 19576 状态字节，单步最多 37 包。完整状态读取仅发生在验证检查点。

100 CPU、原 GPU 守恒、单步反馈与独立 CPU 载液对照回归通过。此结果不扩大物理模型范围：仍两粒点力模型，无气泡/浓相排液，无艺术窗口，且总体计算成本仍高。下一步应在诊断窗口直接显示共同发布的 GPU 状态，并继续解决气泡和固体体积约束，而不是将调度测试当作产品完成。

## 接触移动率适用范围审计

本轮没有修改 GLSL 方程。将原始载液响应提取为 `carrier_response`，审查“保留相互作用、将自响应替换为指定阻力倒数”的修正是否仍耗散。

`python experiments/deposition/mobility_scope_audit.py` 检查 16/32/64 网格、四种恰好接触的粒径与三种阻力，共 36 组。6 组修正矩阵失去正定性。32²、两粒半径 .012、中心间距 .024、阻力 .04 的例子，原始矩阵最小特征值约 4.05，修正后约 -20.43。相向外施力可以得到向内速度，外力功率为负。这不是颗粒重叠或浮点小误差。参数无量纲，尚未对应实物；不能把 6/36 解读为现实失败概率。

完整 CPU 测试 101 项通过（23.976 秒）。新增回归检查原始正耗散、修正负功率与明确拒绝；GPU fixtures 加入 `touching_mobility_rejected`。真实 GPU 标定/接触/反馈测试 7 组零失败，包含该拒绝例及预算耗尽。独立 CPU 压力对照零失败，接受例最大通量差约 1.22e-6。原基线 GPU 1000 tick 守恒回归通过，但不证明液体物理正确。

## 变分排液阻力 CPU 候选

新增 `experiments/deposition/drainage_resistance.py`。冻结当前几何，B 将粒子面积乘速度分配到面上，q 为液相体积通量。约束为 div(q+Bv)=0，封闭边界无外部面。

最小化 `0.5*v^T D v + 0.5*sum(h²*q²/m) - F^T v`，D 为正的背景颗粒阻力。先对各单位粒子速度求最小耗散排液 q，得到 Q；消去液流后 `H=D+Q^T W Q`，移动率为 `H^-1`。因为新增项是半正定 Gram 矩阵，此处无需替换移动率自响应或裁剪负特征值。已有接触求解器直接接受该移动率。

这是独立候选，不是修补后已经验证的悬浮液本构：D 代表背景阻力，并非相对采样液速的滑移阻力；粒子面积通量使用现有平滑核，并未保证局部固相体积分数不超过 1。当前没有演化孔隙率、固相占据量、气泡或壁面润滑。瞬时 div=0 不等于有限步体积输运已经守恒，不能据此替换产品求解器。

自动检查覆盖原 32² 非重叠接触反例的正功率、功率与耗散相等、移动率互易、封闭混合通量平衡、降低渗透率增加阻力，以及支撑静止/反转释放。下一步应建立 B 与固相占据量变化的一致离散，检查移动后的孔隙率与体积误差，再做多颗粒沉积和尺度收敛。当前仅 CPU，未迁移 GPU。


## 圆形颗粒几何体积与有限步排液核验

新增 `disk_volume.py`：解析积分圆与网格单元交集，不归一化补面积；占据率超限、颗粒重叠或穿越封闭网格边界明确拒绝。实际圆盘截过每个面的长度给出固相体积通量 B，新增 `DrainageResistance(..., geometric=True)` 可选择该几何算子；旧平滑核保留作为对照。

有限步固相通量采用 x→y 和 y→x 两条坐标路径的平均，由每行/列占据量变化累加构造，满足 `phi_new-phi_old+dt*div(j_s)=0`。压力补偿通量因此能把旧液相占据量更新到 `1-phi_new`。此通量是几何输运构造，不是碰撞时真实轨迹，不能用中间路径代替接触求解。面截面积的瞬时通量另与占据率的中心差分导数比较。

新增六项测试：16/32/64 网格解析面积、占据导数与面通量、八个角度有限移动的固液平衡、接触与重叠、几何阻力耗散、正反路径与材料身份。`python experiments/deposition/geometric_drainage_cycle.py` 运行四粒 40 步，其中向下 24 步、反转 16 步；逐步保留材料与面积，最大液相占据量误差 2.48e-12。第一次运行因接触默认容差允许的微小穿透被几何检查拒绝；显式将接触容差收紧至 1e-12 后完整通过，未扩大几何容差掩盖问题。

关键未解决项：有限步几何液流与冻结阻力液流最大差 0.033564（无量纲）；因此尚不是非线性一致的液体/接触演化。需步长收敛与一致迭代再评估。几何颗粒小于单元且未切面时瞬时 B 可能为零，存在分辨率依赖；没有渗透率本构标定、气泡排除或 GPU 实现。圆形容器在这些实验里仍是封闭网格掩膜，不能冒充精确圆壁接触。

证据：`reports/geometric-drainage-cycle.json`。本轮没有改动 GLSL；原基线 GPU 1000 tick 守恒通过仅作回归。

## 无显式矩阵排液算子

新增 `matrix_free_drainage.py`，保持冻结几何的同一二次耗散方程。几何 B 只存非零面截面积。一次 `apply(v)` 形成 Bv、解一次封闭压力，得到 q，回传 `Hv=Dv-B^T Wq`。它与参考 `D+Q^TWQ` 等价，不存逐粒压力响应列或完整阻力/移动率矩阵。内层压力源按幅值归一化，外层采用 D 预条件的有界 CG，成功返回前重新计算真实力残差；预算耗尽不返回候选。

四项新测试比较全部矩阵列、耗散、一般重力与分离力下的速度、可变渗透率互易性、零力与预算拒绝。新增算例触发圆盘几乎切过网格面的面积消减问题；修复反导函数中平方根/角度的不一致舍入，改用 `(r-x)*(r+x)` 与 atan2，并将解析非负积分的机器精度负尾差限制为零（不是全局面积归一化）。新增相切回归，仍检查总圆面积。

`python experiments/deposition/matrix_free_benchmark.py` 单次 CPU 自由受力检查：

|---|---:|---:|---:|---:|
| 4 | 299 ms | 174 ms | 8/5 | 7.27e-12 |
| 16 | 1301 ms | 190 ms | 32/5 | 1.35e-9 |
| 36 | 3298 ms | 190 ms | 72/5 | 9.29e-10 |

每档只有一个时间样本，不能据此保证速度提升倍数。三档均 4 次外层迭代加一次真实残差复核；36 粒稀疏 B 为 216 个条目，参考响应列加阻力矩阵为 57312 个标量（未计其它 Python/GPU 内存）。详见 `reports/matrix-free-drainage.json`。

未接入现有接触与自适应周期，不能把自由响应收益当作堆积收益。下一步需要算子形式的接触约束求解，并对照完整矩阵接触解；随后才能决定 GPU 数据流。不改变现有物理适用范围：无气泡/近壁润滑/实物参数标定，新算子只是同一候选方程的不同求解方式。

## 摩擦接触顺序审计与分支重建

`friction_order_audit.py` 在同一 16 粒几何、同一完整移动率下，比较三种遍历顺序和两种松弛系数，分别运行摩擦 .5 与 0，共 12 组。有摩擦时相对原顺序最大速度差 8.07321e-4；无摩擦六组差异均小于 9e-13。所有结果独立力平衡和 Coulomb 约束检查通过。完整速度、接触法向/间隙/反力和初始颗粒已保存至 `reports/friction-order-audit.json`。额外只用对角阻力的 4/9/16 粒对照未复现明显顺序差异，说明此见证依赖摩擦与非局部响应组合，不能泛称所有接触代码错误。

`friction_branch_audit.py` 以原顺序和反序得到的开离/粘着/滑动状态重建线性分支，再求对原结果的最小范数修正。304 维系统数值秩分别为 300/299；修正前后速度变化仅约 1.2e-12，两分支速度差仍为 8.07321e-4。线性残差均约 1.73e-18，独立接触不等式/互补/摩擦耗散误差约 1e-26。它提供当前离散模型不同可行解的浮点证据，不是精确算术唯一性定理。

诊断过程曾直接求最小范数绝对解，虽然线性残差很小，却违反接触不等式（约 1e-4）。已改为从已验证可行解作小修正，并重新检查不等式；不能仅以线性系统解或矩阵秩宣称物理解。最终脚本对证书和分支差异设断言。

决策：原完整矩阵接触结果不能作为唯一物理解 oracle；保留原等价性失败，不将阈值放宽到 1e-3，不把遍历顺序当作艺术随机性。接下来需要评估带接触历史的柔顺/摩擦模型及状态保存，使解选择来自物理历史，而不是求解器偶然顺序。不能预先保证该方案唯一或适合 GPU，仍需耗散、步长和顺序测试。

文献线索：原始研究《On the influence of resolution algorithm’s parameters on the converged solution for a Coulomb friction contact problem exhibiting multiple solutions》https://comptes-rendus.academie-sciences.fr/mecanique/articles/10.5802/crmeca.362/ 。本次可检索到标题/摘要，正文访问 403；未依据未读正文实现算法，也未把文献中的其它问题直接当成本模型的证明。


## 持久切向接触历史：局部本构候选

新增 `tangential_history.py`，独立实现二维切向弹簧/滑块：`xi_trial=xi_old+delta_s`，`xi_new=clamp(xi_trial, -mu*N/k, mu*N/k)`，`F_t=-k*xi_new`。当前法向力 N 是输入，尚未与接触/液体共同求解。切向位移采用连续输运的局部切线坐标；调用方必须使用规范接触朝向并提供接触点相对滑移（含自转时需计入自转）。本模块不实现自转或三维接触坐标输运。

历史按有序稳定整数 ID 对索引，不能使用每帧可重排的数组下标。批量更新创建候选字典，不改旧历史；重复 ID、非法力或中途失败均不提交。消失的接触移除弹簧，释放的储能单独计入损耗；重新接触从新弹簧开始。提供版本 1 JSON 可序列化的接触历史快照与恢复，测试恢复后的后续响应一致。这只是接触子状态，不是应用完整存档功能。

能量核验：输入功 `-F_t*delta_s` 减弹性能变化，等于非负塑性耗散加 `.5*k*(xi_new-xi_old)^2` 的隐式离散耗散。测试覆盖加载/静止持力/卸载反转、滑移上限、300 次变载能量平衡、接触分离、重排、快照恢复、失败保留和非法版本等七项。刚度改变必须显式处理能量，目前拒绝静默修改。

物理参考来自 LAMMPS 官方 granular 文档关于 linear_history 的方程和累积切向位移说明： https://docs.lammps.org/pair_granular.html 。没有复制 GPL 源码，未引入 LAMMPS 依赖。没有照搬其完整阻尼、滚动或三维模型。

下一步需将 `u_t + xi_old/dt + lambda_t/(k*dt)=0` 的粘着关系及滑移边界接入隐式接触求解，并让粒子状态与历史状态共同提交。仍须重跑捕获的顺序敏感网络，不能凭局部回归宣称唯一性已经解决；刚度/时间步/自转及浓相排液的物理标定仍缺失。原库仑等价性失败报告继续保留，未替换 GPU 或主应用。

## 历史/颗粒/液流的有界区间事务

新增 `adaptive_history.py`，外层按有限步几何液流与冻结几何液流之差细分；每次失败只重试当前旧状态，已接受子步才推进局部候选。整个请求区间成功后才返回颗粒、接触历史、累计液流、时间和能量核验。预算耗尽时不返回半完成候选。`MatrixFreeDrainage` 暴露最后一次 apply 的液流，`OperatorHistoryResult` 返回副本，因此误差检查不用重建完整矩阵，也不用额外重算同一冻结液流。

新增测试以非空历史起步，记录已接受时间划分，再显式逐步重放，最终位置和历史完全相同；另注入先拒绝、前半段成功、后半段失败，确认调用方位置和历史均保留。累计液体占据量和接触能量分别核验，重试不累计物理时间或弹簧历史。

`python experiments/deposition/adaptive_history_validation.py` 的一个支撑颗粒、dt=.04、液流误差限 .005：32 子步预算拒绝（29 子步已局部接受，未返回）；最高 64 子步预算内完成，实际 40 子步/79 尝试，最小步长 3.90625e-5，推进时间仍为 .04。最大液流差 .00498663，累计体积误差 2.71e-12，能量误差 2.12e-21。初试更严阈值 .0005/32 子步同样拒绝，未将阈值放宽为“成功”结果；最终采用既有 .005 默认阈值并明确记录预算需求。

该 CPU 单区间耗时约 11.12 秒，远不能实时。不是 GPU 性能结论，也不意味着误差阈值已经物理标定。最小子步集中出现的原因仍需定位，尤其几何面通量与颗粒跨网格位置的关系；不能仅提高子步上限或改渲染帧率来掩盖。当前仍为 CPU 实验，无气泡/自转/实物标定，也未接入应用。

证据：`reports/adaptive-history-validation.json`。下一步应记录触发细分的位置、通量和接触变化，判断是否需要对几何/时间离散作一致改进，再推进 GPU。保留完整产品目标，未将单粒事务通过当作 M2 完成。


## 子步骤增定位：网格面相切与误差量纲

新增可选 attempt trace，不改变接受/拒绝规则；记录每次状态、步长、液流误差最大面、接触反力和拒绝原因。`history_substep_trace.py` 重现 79 次尝试，接触求解失败为 0。最小子步发生在 x≈.491513、半径 .071 的圆盘右缘刚越过 x=.5625 的网格面，距相切位置约 1.34e-5。接触仍为同一支撑壁面，未出现接触网络切换。详见 `reports/history-substep-trace.json`。

`tangency_time_scaling.py`隔离恒速平移、无接触求解的几何算例。步长每缩小四倍，冻结/有限步液流最大差约减半（比例 .50009/.49995/.49995），而冻结通量造成的累计占据率误差约降为八分之一（.12510/.12502/.12501）。解析圆盘截面在相切处是平方根变化；这与观测的差异阶数一致。使用有限步守恒通量更新的占据率误差始终低于 5e-14。证据：`reports/tangency-time-scaling.json`，新增回归核验两种阶数及守恒。

下一步评估一步/两半步的颗粒位置与接触弹性位移差作为状态误差指标，同时保留几何体积及能量约束。必须与更细时间参考比较后才切换默认控制器，并明确误差单位、允许累计误差和工作预算。本轮只补诊断与回归，尚未宣称性能改善或 GPU 可用。


## 一步/两半步状态误差控制候选

新增 `step_doubling_history.py`。对同一旧状态计算完整一步及连续两个半步，比较颗粒坐标和接触弹性位移；只提交两个半步的候选。每个叶区间误差配额按其占请求时间的比例分配，累计估计不超过配置值，但这不是严格的全局轨迹误差上界。最多 32 叶、64 已接受半步、63 次尝试和 189 次接触/排液求解；失败保留整个旧区间。几何液流仍由各已接受半步构造，并核对总液相体积与弹簧功/储能/耗散。

新增三项局部测试：接受步长重放、精度/工作预算拒绝、第二个半步失败时保留位置和历史。完整 CPU 141 项通过（48.970 秒）；原 GPU 基线 1000 tick 零失败。新控制器仍为 CPU 实验。

该候选没有替换既有控制器。比起固定液流误差，状态误差更贴近轨迹验收，但实际性能与严格精度仍未达标；不能把容差放宽一档的结果称为等精度提速。下一步需要复用被拒绝树中已计算的半步并检查局部误差分配成本，继续与细参考对照，再确定 GPU 控制策略。气泡、自转、艺术质量和平台任务仍未完成。


## 子步候选的精确有界复用

实测单次 CPU 开关对照：宽容差耗时 6.86→5.82 秒；严格档仍在第 62 次尝试拒绝，调用由 186 降至 155（31 命中），耗时 25.56→21.42 秒。拒绝边界一致，不能宣称严格档现在可用。不是统计基准或 GPU 性能。

下一步将有参考证据的几何排液与历史接触数据流分段迁移至 GPU，并分别量测；当前 Python 秒级耗时不能直接推导 GPU 成本。状态精度需求与显示尺度尚需明确标定，不能继续用任意更严阈值替代产品验收，也不能通过放宽阈值宣称等精度优化。


`step_doubling_history.py` 增加调用内 LRU 缓存，最多 8 项。键包含完整不可变颗粒状态、有序稳定 ID 的完整弹簧历史和步长；网格、重力、壁面、本构与求解参数在该调用内固定。仅缓存成功候选，不能以“同一时间”替代状态相等；拒绝节点已算出的半步可成为下一节点的粗步。函数结束即释放，不跨物理区间复用。保留 `reuse=False` 独立对照入口。

新增缓存开关的精确相等测试，比较除统计外全部结果：位置、历史、时间、已接受步长、误差估计、累计液流与能量/体积证书。原预算耗尽异常增加仅包含次数的诊断数据，不暴露可误提交的部分状态。没有提高叶节点上限或改变误差阈值。

`step_reuse_validation.py` 比较同一 .04 区间在 1e-4/1e-5 两档容差下的开关结果；接受态逐字段完全相等，拒绝在相同尝试次数发生。数据见 `reports/step-reuse-validation.json`。较宽档压力/接触候选求解调用由 51 降至 43（8 次缓存命中），17 次尝试及已接受路径保持不变。缓存减少重复工作，不改变严格档无法完成的事实。

这只是 CPU 调度层复用，不是 GPU 缓存方案。未来 GPU 若采用类似复用，必须依赖缓冲版本和事务所有权，不能为构造缓存键逐帧读回颗粒。当前候选对象包含接触数组，8 项上限不意味着已经证明大粒子数内存预算达标。


## GPU 切向历史局部核与共同发布

新增 `tangential_history.glsl`：每线程独占一个接触槽，三 pass 分别生成候选/有效性、整批检查、共同发布历史和指标，各 dispatch 间 explicit barrier。状态包含整数稳定 ID、弹性位移和刚度；候选与已发布状态分离。任一槽非法时整批不发布，不使用浮点原子更新物理状态。当前固定槽映射，ID 改变视为错误，尚未实现新接触排序/槽重映射。

运行：

```powershell
python experiments/deposition/tangential_history_fixtures.py
python run.py spring-history
```

130 个槽跨三个工作组、40 次连续事务；36 次接受、4 次拒绝。初始化后 GPU 历史持续保留，CPU 仅提供规定滑移/法向力，没有逐步上传 CPU 历史替代演化。包含加载、反转、法向载荷变化、接触断开/重接。四类错误在最后一个工作组注入：负法向力、改变 ID、改变刚度、NaN；整批旧历史和已发布指标逐字节不变，后续合法输入恢复更新。

CPU oracle 使用相同 float32 输入，独立调用 CPU 弹簧模型并逐步量化保存；检查位移、力、储能、塑性/离散耗散、功和开离损耗。最大位移差约 1.86e-9，最大指标差约 1.42e-7，40 次事务零失败。实机 Godot 4.7.2 / Vulkan / RX 7900 XTX 三 pass GPU 时间中位约 .017 ms；这是局部核时间，不含接触求解、液体压力、上传/读回或渲染，不能外推整帧预算。

验证器使用 local RenderingDevice 的 submit/sync 和全量读回，仅用于测试。生产主设备异步包装尚未接入。物理耦合的法向反力、接触点滑移仍为外部输入，所以此项不是完整 GPU 流沙画或完整接触求解验收。下一步迁移几何面通量算子并与 CPU 对照，随后把历史候选与颗粒候选放入同一物理事务。

证据：`reports/tangential-history-gpu.json`、`reports/spring-history.log`；原 GPU 基线 1000 tick 守恒回归通过。


## GPU 圆盘几何通量与反向力传递

新增 `geometric_operator.glsl`，直接计算圆盘截过网格面的长度，输出固相通量 Bv 和反向项 `-B^T Wq`。不保存 N×面数的完整响应矩阵。每个面只由一个 invocation 写通量，每粒只由一个 invocation 写反向力；当前仍遍历所有粒子/面，没有空间分桶优化。

五 pass 为输入检查、全批证书、候选计算、有限值证书、发布；每个 dispatch 之间 barrier。验证圆盘属性、颗粒重叠、封闭单元边界、液流和正渗透率；计算溢出也会使整批拒绝，输出保持旧字节。GPU 几何容差为 1e-7（无量纲），并不承诺精确算术的零穿透，后续仍需与接触容差统一。

运行：

```powershell
python experiments/deposition/geometric_operator_fixtures.py
python run.py geometric-operator
```

四组有效算例：16² 单粒、32² 接触双粒、16² 相切位置、64² 十六粒。CPU 用相同 float32 输入生成独立几何/功对照；压力 q 由 CPU oracle 求出后输入 GPU，本轮没有声称 GPU 已求解压力。五组拒绝：重叠、越过封闭边界、负渗透率、NaN、有限输入造成溢出。九组零失败，最大通量差 5.17e-8、反向力差 1.51e-10、离散功差 5.18e-11。

首次 shader 编译因 active 为保留字失败，改为 cell_mask 后重跑通过，并补了编译失败释放局部设备的路径。未用编译成功代替数值检查。

## GPU 完整冻结几何排液算子（实验）

新增 `drainage_chain.glsl`、`drainage_chain_validation.gd` 和 CPU fixture 生成器，连接 GPU 圆盘面通量、封闭压力多重网格、液流和反向力传递，输出 `Hv = .04 v - B^T Wq`。液流不再由 CPU 上传；CPU 只提供静态拓扑和独立数值对照。当前 .04 是固定无量纲背景阻力，不是已校准的材料参数。

八组真实 GPU 测试零失败：单粒、接触双粒、相切位置、64² 十六粒、零速度，以及压力预算不足、非法几何、NaN 的整批拒绝。拒绝时最终 H 输出逐字节保持哨兵值；中间源项、压力与液流均为私有候选，未发布为物理状态。各 dispatch 有 barrier、输出无交叠写入。最大液流差 9.62e-7，最大 H 差 1.43e-8。压力使用已有混合阈值 `2e-6 + 4.76837158203125e-7 * max(abs(rhs))`，不能把测得的 1.41e-5 残差描述为达到绝对 2e-6。

限制：给定速度、冻结几何的一次算子调用；未求解接触速度、推进位置或提交切向历史，尚无气泡联动。没有小向量归一化，后续 Krylov 调用前必须处理容差随幅值变化的问题。静态拓扑来自可信 fixture；尚无生产接口验证。验证器使用 local RD 同步读回，仅用于测试；主应用未替换。

复现：`python experiments/deposition/drainage_gpu_fixtures.py`，再运行 `python run.py drainage-chain`。证据为 `reports/drainage-chain-gpu.json` 与 `reports/drainage-chain.log`。下一步优先减少空转调度和全粒/全面遍历，再接入有界接触与历史共同提交，不能将本轮算子验收当成流沙画视觉/物理验收。


## 可复用 GPU 排液调用与失败后继续

## GPU 排液幅值归一化与零输入

可复用排液组件新增 GPU 源项幅值归一化：几何核生成 Bv 后，单个有界 reduction 扫描面通量峰值 s；压力方程使用 Bv/s，求得的液流乘回 s，再计算反向力。s=0 时液流直接置零，保留背景阻力项 .04v。因此速度为零时 H 精确为零，不再残留上一轮压力容差对应的小力。只缩放求解变量，不修改颗粒位置、时间或材料状态。压力缓存现在保存归一化压力，不能作为实际物理压力直接显示。

12 组连续真实 GPU 对照零失败，新增 1e-20 倍速度冷启动、缓存后小输入、1e38 倍有限速度、巨大输入后恢复。误差按输入幅值除回再与 CPU oracle 比较，最大 1.12e-8，未用绝对 1e-7 掩盖小输入相对误差。1e-20 冷启动实际执行 39 个 V-cycle，证明没有直接把小 RHS 当作零接受；零速度 H 精确为零。预算不足和 NaN 仍拒绝且保留旧输出。

极大输入首轮失败；诊断显示几何源项、还原液流及 RHS 的中间运算会出现非有限值。对关键中间量使用 GLSL precise 保留运算次序后，1e38 倍有限输入通过。未声称适用于所有 float32 数值、极小渗透率或退化几何。拒绝/恢复检查继续保留，极大值仅为数值压力测试，不是产品速度范围。

共享 shader 回归：几何九例零失败；三路径排液 72 次零失败且路径间仍字节一致；CPU 142 项通过（53.861 秒）；GPU 基线 1000 tick 零失败。复现 `python run.py drainage-reuse`，详细证据 `reports/drainage-reuse-gpu.json`。新增 scale 缓冲区属于 GPU 私有 scratch，未引入 CPU 中途读回。

仍未接入接触速度求解、位置/历史共同提交或气泡。归一化仅解决试探向量尺度问题，不是完整物理模型验收。下一步应以此组件实现有界 GPU 阻力求解，并比较独立 CPU 速度解，再接触约束。


## 给定外力的 GPU 阻力速度求解

新增 `resistance_solver_gpu.gd` 与 `resistance_solve.glsl`，调用可复用 GPU 排液组件求 `H v = F`。阻尼 Richardson 使用背景阻力 .04 作为预条件、松弛 .8；每次速度修正后重新计算 H(v)，以真实力残差而非递推差判定。外层上限 1–16 次修正，测试配置 8 次；最多 budget+1 次排液调用。压力未收敛时不读取旧 H 更新速度，在剩余外层调用内复用压力重试。预算用尽或非法外力时不发布候选，旧速度逐字节保留。没有 CPU 中途读回，也没有推进颗粒位置。

单粒、相切位置单粒、64² 十六粒三组，各做外力、反向外力、外层预算不足、压力预算不足、NaN、零力、恢复，共 21 情景零失败。成功速度与独立 CPU 矩阵自由求解相比，最大差 2.79e-6。另以 CPU 双精度重新计算每个接受速度的 H(v)，最大力残差 1.17e-7，小于未改变的 2e-7 验收阈值。零力输出为零。这里求得的是固定几何的自由速度，尚不包含接触反力。

初版十六粒失败；重试发现压力残差停在约 1.5e-4 的 float32 舍入量级，单纯增加重复调用没有解决。新增显式可选 backward-error 压力判据：容差为 `2e-6 + 4 eps * max_i(|rhs_i| + sum_j w_ij (|p_i| + |p_j|))`。这比原 RHS-only 判据更宽，明确只由新速度求解器启用，不宣称绝对压力残差达到 2e-6。新接受态十六粒归一化压力残差约 7.9e-4；最终速度仍经独立 CPU 力平衡 2e-7 约束。该浮点误差尺度是工程判据，不是严格误差定理，受压力零点和条件数影响，不能推广为全参数精度保证。非有限误差尺度也拒绝。

单粒三次速度修正、约 31–36 ms；十六粒五次修正、约 85 ms。均为单次 GPU 时间，不含渲染/接触/位置推进。收敛后仍预录剩余排液调用，当前严重浪费，不满足桌面摆件预算。Richardson 对所有正定 H 并不保证以此固定松弛收敛；未覆盖的高阻力条件可能正确耗尽预算，后续需改善求解与调度。
